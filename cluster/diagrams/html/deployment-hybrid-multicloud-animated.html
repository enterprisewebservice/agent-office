Deployment patterns for hybrid and multi-cloud — one definition, many clusters, DNS in front

Connectivity Link has no central management server. Every cluster runs the same Gateway, routes and policies from Git; a DNSPolicy in each cluster publishes one shared hostname with geo, weight and health checks; counters and identity are shared services. The MCP gateway rides the same pattern.

API traffic — clients to whichever gateway DNS names DNS — one hostname, a record per cluster, geo + weight + health configuration — Git, applied by OpenShift GitOps to every cluster shared services — counters, identity, certificates DNSPolicy — a Connectivity Link policy (kuadrant.io) attached to the Gateway; not part of Gateway API

The control plane is Git, not a management server. Add a cluster by pointing GitOps at it; it converges to the same gateway and policies, publishes its own DNS record, and starts taking traffic. Lose a cluster and DNS stops naming it. Everything on this page is generally available in Connectivity Link 1.4.
