One monitoring stack for APIs and MCP — three signals from one gateway

Every API call and every MCP tool call passes the same Envoy, so they produce the same metrics, traces and access logs; the MCP router adds the tool, the server, the session and the caller's identity. Red Hat OpenShift AI adds the view from inside the agent: MLflow traces and EvalHub, on the same OpenTelemetry pipeline.

a request — API call or MCP tool call metrics — OpenShift monitoring, Grafana, Alertmanager traces — Red Hat build of OpenTelemetry, distributed tracing platform logs — Istio Telemetry access log, OpenShift Logging inside the agent — MLflow tracing and EvalHub in OpenShift AI (AgentOps)

One stack, not two. Because APIs and MCP tools cross the same Envoy, the observability you already run for APIs is the observability you get for agents. The additions are the MCP router's headers and spans, one Loki retention policy for the audit trail, and MLflow in OpenShift AI for the view from inside the agent, on the same OpenTelemetry pipeline.
